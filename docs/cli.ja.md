# CLI Usage

YomiToku をコマンドラインインターフェース（CLI）として利用する場合の使い方について説明します。

初回の実行時のみ、Hugging Face Hub からモデルの重みファイルをダウンロードします。
以下のコマンドを実行して、文書画像を解析します。

```bash
yomitoku ${path_data} -v -o results
```

| オプション名 | 説明 |
| :-- | :-- |
| `${path_data}` | 解析対象の画像が含まれたディレクトリか画像ファイルのパスを指定します。 |
| `-o`, `--outdir` | 出力ディレクトリを指定します（なければ作成）。 |
| `-v`, `--vis` | 解析結果の可視化画像を出力します。 |

**補足: `${path_data}` について**

- 画像ファイルまたはディレクトリを指定可能です。
- ディレクトリの場合はサブディレクトリ内も含めて再帰的に処理します。
- 対応ファイル形式は `pdf`、 `jpeg`、 `png`、 `bmp`、 `tiff` です。

!!! note
    - 活字のみの識別をサポートしております。手書き文字に関しては、読み取れる場合もありますが、公式にはサポートしておりません。
    - OCR は文書 OCR と情景 OCR(看板など紙以外にプリントされた文字)に大別されますが、YomiToku は文書 OCR 向けに最適化されています。
    - AI-OCR の識別精度を高めるために、入力画像の解像度が重要です。低解像度画像では識別精度が低下します。画像の短辺を 1000px 以上の画像で推論することをお勧めします。

## ヘルプの参照

`--help`, `-h`にて CLI に指定可能なオプションを表示します。

## 軽量モードでの実行

`--lite`オプションを付与することで、軽量モデルを使用して、推論することが可能です。デフォルトより高速に解析が実行可能です。ただし、文字の認識精度が低下する可能性があります。

```bash
yomitoku ${path_data} --lite -v
```

軽量モードでは、文字認識モデルがコンパクトな `parseq-tiny-dynw-v4`（入力高さ
32px、192 次元、`[4, 8]` パッチ）に切り替わります。このモデルは**動的幅
（dynamic width）**推論向けに学習されており、すべての文字領域を固定の 800px
幅にパディングする代わりに、ミニバッチ内で最も幅の広い領域に合わせてのみ
パディングします。さらに、幅の近い領域をまとめて 1 バッチにする**バケッティング
（batch bucketing）**を行います。実際の文字領域の多くは幅が狭いため、無駄な計算
が大幅に削減され、特に CPU で高速になります。CPU 実行時はテキスト検出器を ONNX
ランタイムで動かし、認識のミニバッチを並列に実行します。

軽量モデルの重みは初回実行時に Hugging Face Hub
（`KotaroKinoshita/yomitoku-text-recognizer-parseq-tiny-dynw-v4`）からダウンロード
されます。

## 出力フォーマットの指定

`-f`, `--format` 出力形式のファイルフォーマットを指定します。(json, csv, html, md, pdf(searchable-pdf) をサポート)

```bash
yomitoku ${path_data} -f md
```

`pdf` を指定した場合、画像内の文字情報を認識し、文字情報を透明テキストとして埋め込むことでサーチャブル PDF に変換します。

## 出力デバイスの指定

`-d`, `--device` オプションを使用することで、モデルを実行するためのデバイスを指定します。(cuda | cpu | mps)。gpu が利用できない場合は cpu で推論が実行されます。(デフォルト: cuda)

```bash
yomitoku ${path_data} -d cpu
```

## 改行の無視

デフォルトでは、画像内で記述された情報に従い、改行を行います。 `--ignore_line_break` オプションを使用することで、画像の改行位置を無視して、段落内の同一文章を連結して返すことが可能です。

```bash
yomitoku ${path_data} --ignore_line_break
```

## 図やグラフ画像の出力

デフォルトでは、文書画像内の含まれる図や画像の情報を出力しません。`--figure`オプションを使用することで、文書画像に含まれる、図や画像を切り出し、個別の画像として保存、また、出力ファイル内に検出した個別の画像に対するリンクを出力します。

```bash
yomitoku ${path_data} --figure
```

## 図や画像内に含まれる文字の出力

デフォルトでは、図や画像内に含まれる文字情報は出力ファイルに出力しません。 `--figure_letter` オプションを使用することで、画像や図に含まれる文字情報も出力ファイルに出力します。

```bash
yomitoku ${path_data} --figure_letter
```

## 出力ファイルの文字コードの指定

出力ファイルの文字コードを`--encoding`オプションにて指定できます。(utf-8, utf-8-sig, shift-jis, enc-jp, cp932)。サポートされていない文字コードが含まれる場合は、その文字を無視し、出力しません。

```bash
yomitoku ${path_data} --encoding utf-8-sig
```

## Config のパスの指定

次のオプションで各モジュールに対する Config が記述された YAML ファイルへのパスを指定します。

| オプション名  | 対象モデル |
| :--- | :--- |
| `--td_cfg` | Text Detector (文字位置の検知) |
| `--tr_cfg` | Text Recognizer (文字列認識) |
| `--lp_cfg` | Layout Parser (レイアウト解析) |
| `--tsr_cfg` | Table Structure Recognizer (表の構造認識) |

```bash
yomitoku ${path_data} --td_cfg ${path_yaml}
```

## メタ情報を出力ファイルに加えない

ヘッダーやフッター等のメタデータを出力ファイルに加えないようにすることができます。

```bash
yomitoku ${path_data} --ignore_meta
```

## 表のセルをまたぐテキストを分割する

テキスト検出で複数の表セルにまたがって1行として検出されたテキストを、セル境界で分割してから認識します。セル内の文字列がより正確に各セルへ割り当てられます。

```bash
yomitoku ${path_data} --split_text_across_cells
```

## 複数ページを統合する

PDFに複数ページが含まれる場合に複数ページを一つのファイルにまとめてエクスポートできます。

```bash
yomitoku ${path_data} -f md --combine
```

## PDF出力の画質設定

サーチャブルPDFを出力する際の画質プリセットを `--pdf_quality` で指定できます。デフォルトは `high` です。

| プリセット | 長辺の最大サイズ | JPEG品質 | 説明 |
| :--- | :--- | :--- | :--- |
| `high` | 制限なし | 85 | 高画質（デフォルト）。元画像の解像度を維持します。 |
| `middle` | 2000px | 80 | 中画質。ファイルサイズと画質のバランスを取ります。 |
| `low` | 1500px | 60 | 低画質。ファイルサイズを最小限に抑えます。 |

```bash
yomitoku ${path_data} -f pdf --pdf_quality middle
```

## PDFの読み取り解像度の設定

PDFを読み取る際の解像度の大きさを設定します(標準DPI=200)。PDF内の文字が微細な場合など、細部の文字を読み取りたい場合にDPI値を上げることで読み取り精度が向上する場合があります。

```bash
yomitoku ${path_data} --dpi 250
```

## 読み取り順を指定する

デフォルトでは読み取り順のオプションは `auto` に設定します。

`auto` が指定されている場合、システムは文書の向き（横書きか縦書きか）を識別し、読み取り順を自動で推定します。
具体的には、横書きの文書は `top2left` 、縦書きの文書は `top2bottom` と推定されます。

読み取り順は、以下のように手動で指定することも可能です。

```bash
yomitoku ${path_data} --reading_order left2right
```

| 設定名 | 優先される読み取り順 | 有効なドキュメントのタイプ |
| :--- | :--- | :--- |
| `top2bottom` | 上から下方向 | 段組みのワードドキュメントなど |
| `left2right` | 左から右方向 | レシートや保険証など、キーと値が段組みになっているレイアウト |
| `right2left` | 右から左方向 | 縦書きのドキュメント |

## 認識方向フォールバックの有効化

デフォルトでは、認識方向フォールバックは無効化されています。`--enable-rec-orientation-fallback` オプションを使用することで、文字認識の信頼度が低い場合にROI画像を180度回転して再認識を行い、信頼度が高い方の結果を採用する機能を有効化できます。

```bash
yomitoku ${path_data} --enable-rec-orientation-fallback
```

`--rec-orientation-fallback-thresh` オプションで、フォールバックを実行する信頼度の閾値を指定できます。（デフォルト: 0.75）

```bash
yomitoku ${path_data} --enable-rec-orientation-fallback --rec-orientation-fallback-thresh 0.6
```

## 繰り返し抑制の無効化

文字認識では、同じ文字や文字列が異常に繰り返されるループを検出すると、その時点でデコードを打ち切り、繰り返しを1回分に縮約します。この機能はデフォルトで有効です。リーダー（`……`）や記号の長い連続など、繰り返しをそのまま出力したい場合は `--disable-repetition-stop` で無効化できます。

```bash
yomitoku ${path_data} --disable-repetition-stop
```

判定の閾値は `--tr_cfg` に渡す YAML で調整できます。詳しくは[モデルの詳細設定](configuration.md)を参照してください。

## ふりがな（ルビ）の除外

文書画像に含まれるふりがな（ルビ）テキストを出力から除外することができます。`--ignore_ruby` オプションを使用すると、各段落・セル内の文字の行高さの中央値に対して一定の閾値未満かつ、ひらがなのみ・カタカナのみで構成されるテキストをルビとみなし、除外します。

```bash
yomitoku ${path_data} --ignore_ruby
```

`--ruby_threshold` オプションで、ルビ判定の閾値を調整できます（デフォルト: 0.5）。値を大きくするとルビと判定される範囲が広がります。

```bash
yomitoku ${path_data} --ignore_ruby --ruby_threshold 0.6
```

## 読み取り対象ページを指定する

特定のページのみを対象として処理することが可能です。処理対象のページをコンマ区切り、もしくはハイフンによって連続するページを指定できます。

```bash
yomitoku ${path_data} --pages 1,3-5,10
```

## 幾何補正(歪み補正)

`--dewarp` オプションを使用すると、スマートフォン等で撮影した文書の湾曲・カール・傾き・台形の歪みを補正してから解析します。補正後の画像は行やレイアウトがまっすぐになるため、OCR とレイアウト解析が安定します。

紙の輪郭を抽出して四隅を射影変換するだけの単純な補正ではなく、紙面全体の歪みを推定する非線形な補正のため、紙の湾曲やカールも平らに戻せます。紙の一部が画像の外に見切れている写真や、影・照明ムラのある写真にもロバストです。

デフォルトのモデル(`pagenet_v1`)は、1 枚の画像に写っているすべてのページ(見開きの左右のページ、並べた名刺やレシートなど)を検出し、ページごとに補正して解析します。見開きは綴じ部分で左右 2 ページに分けて出力します。

```bash
yomitoku ${path_data} -v --dewarp
```

| オプション名 | 説明 |
| :--- | :--- |
| `--dewarp` | 幾何補正を有効にします。 |
| `--dewarp_coordinate` | 出力座標を指定します。`dewarped`: 補正後の画像の座標(デフォルト)、`photo`: 元の画像の座標。 |
| `--dewarp_model` | 幾何補正モデルを指定します。`pagenet_v1`: 画像内のすべてのページを検出して補正(デフォルト)、`uvdoc_v1`: 画像全体を 1 ページとして補正。 |
| `--dewarp_cfg` | 幾何補正モデルの Config(YAML)のパスを指定します。 |

出力ファイル:

| ファイル | 説明 |
| :--- | :--- |
| `*_dewarped.jpg` | 補正後の画像(補正に成功した場合のみ)。`dewarped` 座標の解析結果はこの画像上の座標です。 |
| `*_dewarp_grid.jpg` | `--vis` 指定時のみ。`pagenet_v1`: 検出したページごとに、ページ全体の Grid(細線)、補正して切り出した範囲(太線)、ページ番号と検出スコアを描画します。`uvdoc_v1`: 推定した紙の領域(黄線、紙の外は暗く表示)と、補正後の画像の行(赤線)・列(青線)が元の画像のどこに対応するか(Grid)、補正後の画像の外枠(緑線)を描画します。 |

`pagenet_v1` で 1 枚の画像から複数のページが見つかった場合、ページごとの出力ファイルは `*_p{ページ番号}_{k}.*`(`k` は左から右、上から下の順に 1 から)になります。ページが 1 つの場合は従来どおり `*_p{ページ番号}.*` です。`*_dewarp_grid.jpg` は画像ごとに 1 つ出力されます。`--combine` で 1 ファイルにまとめる場合、Markdown / HTML ではページの間に区切り線(`---` / `<hr>`)と、ページを示すコメント(`<!-- page p1_2 -->` など)が入ります。

`--dewarp_coordinate photo` を指定すると、補正後の画像で解析した結果を元の画像に逆投影して出力します。各要素(段落、表、セル、図、単語)に元の画像上の曲がった多角形 `polygon` が付与され、`box` はその外接矩形になります。可視化画像も元の画像上に描画されます。

```bash
yomitoku ${path_data} -f json -v --dewarp --dewarp_coordinate photo
```

### 補正失敗の検知

補正の推定結果が壊れていると判定した場合(紙の領域と Grid が一致しない、Grid が折り返している、など。`pagenet_v1` ではページが見つからない場合)、そのページは補正せずに元の画像のまま解析を続行し、ログに警告を出力します。`pagenet_v1` では、Grid が潰れたページ、より大きなページの内側にあるページ、画像の外に大きく見切れたページ(見開きの端に写った隣のページなど)は、補正・解析の前に除外します。結果は JSON の `preprocess.dewarp` に記録されます。

```json
"preprocess": {
  "dewarp": {
    "status": "ok",
    "reasons": [],
    "coordinate": "dewarped",
    "size": [6792, 4120],
    "mask_iou": 0.9995,
    "flipped_cells": 0.022,
    "spacing_ratio": 2.34,
    "outside": 0.082
  }
}
```

| フィールド | 説明 |
| :--- | :--- |
| `status` | `ok`: 補正済み、`rejected`: 補正失敗と判定し、補正せずに解析 |
| `reasons` | `rejected` の理由(`uvdoc_v1`: `mask_iou`, `flipped_cells`, `spacing`, `outside`、`pagenet_v1`: `no_page`) |
| `coordinate` | 解析結果の座標系(`dewarped` / `photo`)。`rejected` の場合は常に `photo` |
| `size` | 補正後の画像のサイズ `[幅, 高さ]` |
| `mask_iou` | 推定した紙の領域と Grid の外形の IoU(`uvdoc_v1` のみ) |
| `flipped_cells` | 裏返った Grid セルの割合 |
| `spacing_ratio` | Grid の最長の辺 / 辺の長さの中央値 |
| `outside` | 画像の外に大きくはみ出した Grid 点の割合 |
| `page` | `pagenet_v1` のみ。画像内で見つかったページのうち何番目か(0 から、左から右、上から下の順) |
| `num_pages` | `pagenet_v1` のみ。画像内で見つかったページの数 |
| `score` | `pagenet_v1` のみ。ページ検出のスコア |

!!! note
    - 幾何補正はスマートフォン等で撮影した文書画像を対象としています。スキャン画像や PDF など、もともと平らな文書画像には使用しないでください。紙の輪郭がないため補正の効果がなく、わずかに歪む場合があります。
    - 折り目の補正効果は限定的です。
    - 補正後の画像では、紙の外の領域(机や画像の外)は紙の色で塗りつぶされます。
